# JobPipe project entry

This is a locator, not a copy of the project's business rules.

1. Inspect this plugin using `muse plugins inspect jobpipe-observer --json`. Read `record.source.path`, which points to the original `integrations/muse/jobpipe-observer` directory. The project root is three parents above that path. Do not infer it from the plugin cache or Muse's current working directory.
2. Verify that the original project exists and contains `AGENTS.md`, `docs/skill/inbox-contract.md` and `scripts/muse-start.ts`. If missing or moved, stop and ask the user to repair the binding in JobPipe Settings; do not choose another project silently.
3. Read the original root `AGENTS.md`, then its authoritative inbox contract and stage-specific documents. Do not use an archived or copied policy. All operational writes go to inbox; Engine owns business files; user approval is required before submission.
4. For a new operational run, use the command generated by that project's Settings page or `node scripts/muse-start.ts --stage <stage> --task-file <absolute-task-file> --trust-workspace` from the project root. This fixes the workspace and loads an Engine-built context snapshot. Do not recursively spawn another Muse run when already inside one with the appropriate loaded context.
5. A session opened elsewhere does not acquire live reporting simply by reading this Skill. Do not start applications until workspace, context and reporting are aligned. Never create a detached heartbeat to imitate an active job.
6. Read non-secret preferences from the context package. Account creation methods and vault references belong in Engine-committed Knowledge entries tagged `agent-context`; never put credential values in this Skill, logs or Activity.
